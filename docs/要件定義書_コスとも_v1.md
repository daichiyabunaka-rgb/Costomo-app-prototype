**バージョン**: v1.0（ドラフト）

**作成日**: 2026年2月

**参考**: 第4弾「ニーアキャット（猫とも！）」の要件定義書・実装（Nekotomo-app-prototype）を本アプリ（コスプレ版）のドメインに適用。

## 1. 概要

### 1.1 目的

コスプレ好き同士を、**本人の素顔ではなく趣味・中身ベース**でマッチングし、以下を実現する。

1. 一般ユーザー同士：今から・近くで、撮影仲間・コス仲間（撮影会・交流）を探して一緒に遊ぶ
2. 一般ユーザー：近くの撮影スポット（公園・神社・イベント会場）を探してGoogleマップで開く
3. 一般ユーザー：使わなくなった衣装・ウィッグ・小物を近隣で無償でゆずりあう・交換する
4. ビジネスユーザー：AI接客・地図連携で、近隣のコスプレイヤーに店舗（フォトスタジオ・衣装店等）を知ってもらい来店へつなげる
5. コミュニティ：作品別・ジャンル別のサークル、撮影会・オフ会などのイベント企画

### 1.2 コンセプト上の設計原則

| 原則 | 内容 |
|---|---|
| 本人の素顔画像禁止 | プロフィール画像は「コスプレに関連する画像のみ」許可（キャラの姿・衣装・ウィッグ・撮影風景など。**キャラの姿はむしろ推奨**）。本人の素顔がメインの画像はアップロード不可（モデレーションで拒否・削除） |
| 恋愛目的禁止 | 利用規約で「恋愛・異性交際目的の利用」を明示的に禁止。違反は BAN 対象 |
| 金銭取引禁止 | ゆずりあい・交換は無償の譲り合い・物々交換のみ。売買・オークション的な利用は禁止 |
| 時限性 | 募集は期限付き（1〜3時間）。期限が来たら自動消滅。「今から」感が出会い系化を防ぐ |
| 距離の粗表示 | 正確な位置は非公開。「〜1km / 1〜3km」のような大ざっぱな距離のみ表示 |
| 撮影マナー尊重 | 公園・神社・お寺等での撮影は管理者・撮影許可の事前確認を必ず案内する文言・機能設計 |

### 1.3 前提と未確定事項（法務レビュー必須）

| 項目 | v1 の対応 | 備考 |
|---|---|---|
| 出会い系サイト規制法 | サービスの実質を「撮影仲間・趣味仲間探し」とし、規約・モデレーションで異性交際目的利用を排除 | 弁護士による非該当性確認を必須とする。素顔画像禁止（コスプレ画像のみ許可）・一言メッセージ制は非該当性の根拠になる設計 |
| 未成年利用 | **v1 は18歳以上のみとする**（シリーズ各弾と同じ） | 未成年対応は v2 以降で法務確認の上検討 |
| 肖像権・著作権 | 版権キャラクターの衣装製作・撮影は私的範囲と案内し、**無断の商用利用（有償撮影会・販売）を禁止**する規約を整備 | 業態別ガイドライン整備が必要 |
| 撮影場所の許可 | 神社・公園等での撮影は事前に管理者へ確認する旨を募集・スポット画面に常時案内。商業施設（cafe等）は検索対象に含めない | 各施設の撮影規則の周知徹底 |
| 迷惑防止条例（客引き） | ビジネスユーザーの営業・AI接客はアプリ内完結とし、押しつけのない設計（一斉配信はしない）。オプトアウト手段を常時提供 | 個別自治体への確認は開発中に実施 |
| 個人情報保護法 | 位置情報・嗜好データの第三者提供は「匿名加工統計」に限定 | 店舗ダッシュボードには集計値のみ表示 |
| 受け渡しの安全 | ゆずりあい・交換の受け渡しは公共の場・イベント会場を前提とし、個人の自宅住所等を記入させない案内。金銭授受・送金を伴う取引は禁止 | トラブルを想定した免責規約の整備 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 一般ユーザー | 無料で利用するコスプレ好き（個人）。コスともを探す側 |
| ビジネスユーザー | 有料プランで登録する店舗・事業者・個人営業主（フォトスタジオ、イベント会場、ホール・劇場、衣装・ウィッグ店、コスプレ用品店、小物・道具工房、撮影・レタッチ代行など） |
| 募集（Recruitment） | ユーザーが近隣に向けて時限で発信する「参加者募集」（撮影会 / イベント / 交流・雑談）。投稿から1/2/3時間後に自動消滅 |
| 応募（Application） | 募集への参加申請。主催者が承認するとグループチャットが生成される |
| コミュニティ | 常設のグループ（作品別・ジャンル別サークル、スタジオ常連会等）。誰でも作成可、参加自由（承認制も選択可） |
| イベント | コミュニティまたは個人が企画する日程付きの集まり（撮影会、コラボ企画など） |
| 撮影スポット検索 | 現在地近くの撮影に使える公共の場（公園・神社・お寺・イベント会場・ホール）を一覧表示し、Googleマップ（標準URL）で開ける機能。ワンタップで「その撮影スポットで募集」も可能 |
| ゆずりあい・交換 | 使わなくなった衣装・ウィッグ・小物を近隣で無償でゆずる・探す・交換するボード。金銭取引は禁止 |

## 4. ペルソナ

### 一般ユーザー
- 20代〜40代、イベントや撮影会に年参加するが、誘い合える相手が少ない・引っ越して撮影仲間がいない
- 「週末に公園で和装撮影をしたいが、撮ってくれる相手・被写体がいない」「同じ作品のコス仲間と撮影会を開きたい」
- 恋愛マッチングアプリには抵抗がある（恋愛目的でない人）
- 衣装・ウィッグが増えてしまったので、誰かへ無償でゆずりたい

### ビジネスユーザー
- フォトスタジオ・イベント会場・衣装・ウィッグ店・撮影代行等の経営者
- 「閑散時間に撮影予約を増やしたい。近くのコスプレイヤーとの接点が少ない」「AI接客で問い合わせ対応と、地図から来店への導線を強化したい」
- 月額数千円〜1万円程度の予算感で、新規顧客よりも「リピーター・常連コミュニティ」を増やしたい

## 5. 機能要件

### 5.1 会員登録・認証

| 要件 | 内容 |
|---|---|
| FR-1-1 | SNS 認証（Apple / Google / LINE）。v1 では電話番号認証を必須としないが、通報対策としてアカウント単位のレート制限を実装 |
| FR-1-2 | 登録時の必須入力：ニックネーム、年代（10歳刻み表示、生年非公開）、性別（非公開も選択可）、居住エリア（市区町村レベル）、興味カテゴリ（複数選択：アニメ / ゲーム / 漫画・ラノベ / 特撮 / VTuber / ボカロ・音楽 / コスプレ撮影 / 加工・動画編集 / イベント参加 / ウィッグ・衣装制作 / ダンス・コラボ 等 11種＋ユーザー自由追加）、ジャンル・作風の自由記述（140字、「コスともステータス」） |
| FR-1-3 | **アイコンは写真アップロードまたは提供アイコンセットからの選択**。アップロード画像は **本人の素顔** を AI 顔検出で自動審査する方針（本開発）。**キャラ姿（メイク・ウィッグ含む衣装の画像）の投稿は許可（推奨）** |
| FR-1-4 | 年齢確認：生年月日を入力させる（18歳以上チェック用）が、プロフィールには公開しない |
| FR-1-5 | 退会：アカウント削除時のデータ保持期間（アクティブデータ即時削除、バックアップ90日）を規約に明記 |

### 5.2 近くのコスとも・募集（コア機能）

| 要件 | 内容 |
|---|---|
| FR-2-1 | 「募集をかける」：以下を指定して募集を発信できる |
| | - ジャンル（撮影会 / イベント / 交流・雑談） |
| | - タイトル・本文（例：「今から中央公園で和装撮影しませんか。撮影係・被写体どちらも歓迎」） |
| | - 条件設定：性別指定（任意）、人数上限、作品・キャラの言及（自由記述） |
| | - 有効期限（1 / 2 / 3 時間、期限切れで自動消滅） |
| | - 待ち合わせ場所：撮影スポット名（「近くの撮影スポット」タブからワンタップで設定可） |
| FR-2-2 | 「近くの人」リスト：現在地から粗い距離（〜1km / 1〜3km / 3〜5km / 5〜10km）で、近くのアクティブな募集・ユーザーを一覧表示。並び替え：距離×新着 |
| FR-2-3 | 検索：ジャンル、キーワード、距離、興味カテゴリでフィルタ可能。「探す」タブからは近くの店舗（業態・店名で検索可）と近くのコミュニティ・イベント（距離近い順）も辿れる |
| FR-2-4 | **近くの撮影スポット検索（本アプリの特別機能）**: 現在地周辺の実在の撮影スポットを OpenStreetMap（Overpass API）から取得し、近い順に一覧表示（距離バンド、営業時間）。対象は**公園（leisure=park）・神社・お寺（amenity=place_of_worship）・イベント会場・ホール（events_venue / arts_centre / exhibition_centre /theatre）**のみ。**商業施設（喫茶店・民間フォトスタジオ等）は一覧に含めない**。神社・お寺は「撮影前に社務所・管理者へ必ず確認」の注意文言を常時表示する。Google Maps（Places API）との連携は本リリース時のオプションとして見送り。各スポットは「Googleマップで開く」（座標指定の標準URL）でGoogleマップに遷移する。「この撮影スポットで募集」ボタンで待ち合わせ場所を初期設定した募集を作成できる |
| FR-2-5 | 募集は同一ユーザーが同時に1件まで（スパム防止） |

### 5.3 応募・交流

| 要件 | 内容 |
|---|---|
| FR-3-1 | 応募：募集詳細から「参加したい」ボタンで応募。一声メッセージ（任意、140字） |
| FR-3-2 | 主催者は応募一覧から承認／却下。承認人数が上限に達したら募集は自動的に締切 |
| FR-3-3 | 承認されたメンバーでグループチャットが自動生成。参加者はその後も辞退可能 |
| FR-3-4 | 1:1 のダイレクトメッセージは募集への応募経由でのみ送れる設計（いきなり DM される対策） |
| FR-3-5 | 万一に備えた安全機能：ブロック／通報は一般ユーザー間と同一水準。初対面の撮影会・受け渡しは「公共の場で」「第三者がいる場所で」行うよう投稿時に案内 |

### 5.4 プロフィール・中身重視設計

| 要件 | 内容 |
|---|---|
| FR-4-1 | 趣味・嗜好の表現をリッチにする（得意ジャンル、撮影の好み、衣装自作/既製の別、イベント参加頻度）を「コスともステータス」としてマイページに表示 |
| FR-4-2 | 過去の参加募集数、参加者からの評価（「また一緒に遊んだ」ボタン式、v1.5 実装）を表示 |
| FR-4-3 | ブロック／通報：非表示、通報（理由入力）。通報数が閾値超過で自動凍結 → 人力審査 |

### 5.5 ビジネスユーザー（v1.5）

| 要件 | 内容 |
|---|---|
| FR-5-1 | 店舗登録：店舗名、業態（審査対象：フォトスタジオ、イベント会場、ホール・劇場、衣装・ウィッグ店、コスプレ用品店、小物・道具工房、ダンススタジオ、撮影・レタッチ代行、その他）、住所、営業時間、写真（店舗・作品例 OK。**本人の素顔写真禁止は一般ユーザーと同じ基準**） |
| FR-5-2 | **AI接客（有料機能）**: ビジネスユーザーは店舗情報を登録するだけで、AI（LLM）が来店前の質問対応・案内（撮影プラン、料金、衣装持ち込みの可否、営業時間等）を行う |
| FR-5-3 | **地図連携**: 近くの店舗をアプリ内マップ（OpenStreetMap タイル、APIキー不要）にピン表示。各店舗は「Googleマップで開く」（標準URL）。本開発で Google Maps SDK に移行し経路案内まで表示 |
| FR-5-4 | 効果測定: AI接客の応答数・来店導線・閑散時間のアクセス推移を店舗ダッシュボードに表示 |
| FR-5-5 | 課金：月額制（ライト／スタンダード／プレミアム）。決済は Stripe / RevenueCat 等の標準的な手段を利用 |

### 5.6 コミュニティ・イベント

| 要件 | 内容 |
|---|---|
| FR-6-1 | コミュニティ作成：誰でも可（名前、説明、カテゴリ、公開／承認制、地域）。作品別サークル、スタジオ常連会、撮影テクニック研究等 |
| FR-6-2 | イベント：コミュニティに紐付けて日程・撮影スポット名・募集人数を設定し、参加受付 |
| FR-6-3 | ビジネスユーザーも一般ユーザーも同じコミュニティに参加可 |
| FR-6-4 | コミュニティ一覧（参加中・未参加とも）は**近い順にソート**する。コミュニティ自身の位置情報は持たず、メンバー・主催者の中で最も近い人までの距離で近さを定義する |

### 5.7 撮影報告（旧・ゆずりあい・交換、2026-11-18変更）

| 要件 | 内容 |
|---|---|
| FR-7-1 | 登録: 種別「撮影」（shoot）/「場所」（spot）/「イベント」（event）/「絵」（art）を、タイトル（キャラ名・作品名など）、撮影した場所（「絵」は任意・未入力可）、撮影状況・ハイライトの自由記述、**写真1枚（任意。ギャラリー/カメラ）**を入力して報告できる。位置は報告時の現在地（geohash）のみを持つ |
| FR-7-2 | 検索: 近くの報告を**距離近い順**に一覧。撮影／場所／イベント／絵で絞り込み可。投稿者へのDM導線（一緒に撮ろう・描いてほしい等の交流）を同画面に持つ |
| FR-7-3 | 解決: 投稿者は「完了にする」を設定でき、完了は一覧から表示しない |
| FR-7-4 | 法務・安全設計: **本人・撮影者の許諾を得た画像のみ投稿可**。他人の無断撮影・無断転載・性的な内容は禁止案内で排除（通報・削除対象）。権利関係（肖像権・著作権・トレパク）の遵守を常時案内。旧「ゆずりあい・交換」にあった金銭取引禁止・受け渡し文言は本機能の廃止に伴い削除 |

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| プラットフォーム | iOS / Android（Flutter）。Web 管理画面（モデレーション用） |
| 位置情報プライバシー | 位置情報は端末側で geohash（精度レベル5〜6程度）に変換して送信。サーバーには生の緯度経度を保持しない。退会時に即時削除 |
| セキュリティ | TLS 通信、認証トークン（短期＋リフレッシュ）、パスワードレス（SNS認証） |
| 応答性能 | 募集の一覧取得は P95 200ms 以内（キャッシュ活用）。プッシュ通知は P95 30秒以内 |
| 拡張性 | 趣味カテゴリ（第1弾:飯とも、第5弾:コスとも、次弾:車/バイク/キャンプ等）はマスタデータ化し、アプリ再リリースなしで追加可能 |
| モデレーション | AI 審査（**本人の**素顔画像検出、禁止ワード）＋人力審査ワークフロー。通報 → 凍結 → 審査の SLA 48時間 |
| アナリティクス | 登録 → 募集投稿 → 応募 → 成立（チャット生成） → 実参加（チェックイン）→ リピートのファネル KPI を計測 |


設計メモ：
- 募集の期限切れは毎分のバッチで `status` を `expired` に更新。クライアントは `_expires_at` を見て表示制御も行う（二重防護）
- 撮影スポットは外部データ（Google Places / OSM）を `spots` に同期し、`google_place_id` で「Googleマップで開く」URL を組み立てる
- ゆずりあい・交換は geohash 先頭4桁一致（約20km四方）を「近く」とする
- 距離検索は geohash プレフィックス照合で実装し、生の緯度経度での距離計算はクライアント側で行わない

初期はジャンルの近さよりも「募集あたり応募数」が最重要。1.0を下回る場合、リリース地域を都市部のイベント・撮影スポット密集地に絞る。

## 10. カテゴリ拡張戦略

第1弾「飯とも」〜第5弾「コスとも！」で共通のプラットフォーム（認証・募集・コミュニティ・地図連携・ビジネス課金）が確立できた前提で、次に拡張するカテゴリは以下の基準で選ぶ：

1. 一般ユーザーの行動頻度が高い（週1回以上）
2. ビジネスユーザーが明確に存在し、課金対象（AI接客・地図連携）になる
3. 周囲への「募集」が自然に多発する（ナインモンスターズ的方式の近隣勧誘が機能する）

この基準でいえば、「コスとも！」はビジネスユーザー（フォトスタジオ、イベント会場、衣装・ウィッグ店）が明確で収益性が高い。かつ「近くの撮影スポット」「ゆずりあい・交換」という2つの特別機能でオフライン行動とモノの循環を促進できる。次弾は「車/バイク」（ガソリンスタンド、カー用品店）→「キャンプ」（アウトドアショップ）を検討。
